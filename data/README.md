# Atlas synthetic dataset

This directory holds the synthetic dataset Atlas's agents read from. It was
generated by `scripts/generate_data.py` per `docs/data-generation-spec.md`.

## Reference date

All files share a single reference date — treated as "today":

```
2026-05-19
```

The 12-month activity window runs **2025-05-19 → 2026-05-19**. Some
contract dates (account-level `contract_start` / `contract_end`) intentionally
fall outside the window (older starts, future-dated renewals) — only event
timestamps are constrained to the window.

## Files

| File | Records | Notes |
| ---- | ------- | ----- |
| `accounts.json` | 25 | Strategic enterprise accounts. |
| `users.json` | ~390 | Users across all accounts. Each has an `account_id`. |
| `support_tickets.json` | ~510 | Tickets with subject, body, sentiment, category. |
| `usage_events.json` | ~11.6k | Weekly aggregates — see "Granularity" below. |
| `call_summaries.json` | ~195 | Sales / CS call summaries with topics and action items. |
| `cs_notes.json` | ~180 | CS notes by category (relationship, risk, opportunity, general). |
| `cross_functional_signals.json` | ~60 | Free-form risk / opportunity / observation signals from various functions. |
| `roadmap.json` | 15 | The mock product roadmap. |
| `ground_truth.json` | sealed | **Do not read from agents or backend.** See below. |

## Granularity (usage_events)

`usage_events.json` is aggregated to **one row per (account, feature, week)**
rather than per individual user action. Each row carries:

- a representative `timestamp` somewhere within that week,
- a single `user_id` sampled from the account's user pool for that row,
- an `event_type` (`feature_use` is dominant; a minority are `login` or `api_call`),
- `duration_seconds` proportional to that week's aggregate activity.

This preserves 60-day trend detectability for the agents while keeping the file
under ~12k rows.

## Canonical feature names

The same fixed set of feature names is used across `usage_events.json`,
`support_tickets.json` bodies, `call_summaries.json` topics, and `roadmap.json`:

- `docs`           — **core feature**
- `shared_drive`
- `meetings`
- `workflows`
- `chat`
- `calendar`
- `search`
- `admin_console`  — the feature tied to the **Systemic Product Signal** pattern
- `mobile_app`
- `integrations`

`roadmap.json` separately includes invented forward-looking items
(e.g. `AI meeting summaries`, `Workflow templates v2`); these are roadmap
features, not usage features.

## ground_truth.json — DO NOT READ FROM AGENTS

`ground_truth.json` is the sealed answer key for evaluation. Only the
evaluation harness (`eval/`) is permitted to read it. Agent code (`agents/`)
and the backend (`backend/`) must never import it, reference its path, or
log its contents.

Atlas's credibility as a portfolio piece rests on this boundary: if the
agent has seen the answer key, the evaluation says nothing about whether
the system can actually surface patterns it was never told about.

## Regenerating

```
python scripts/generate_data.py     # regenerate all 9 files
python scripts/validate_data.py     # run the usability checklist
```

The generator is deterministic for its hard-coded seed
(`SEED = 20260519` in `scripts/generate_data.py`).
